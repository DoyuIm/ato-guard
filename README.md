# ATO Guard

로그인 계정 탈취(Account Takeover)를 **규칙 + 이상 탐지 모델 + 위험도별 대응** 3단계로 막는 파이프라인 PoC입니다.
실서비스 로그 대신 합성 로그인 로그(사용자 500명, 60일)로 섀도 모드까지 검증합니다.

## 막는 위협

- **크리덴셜 스터핑**: 유출된 ID/PW를 데이터센터 IP 여러 개로 짧은 시간에 대량 대입
- **표적 계정 탈취**: 해외·새벽·새 기기 로그인 직후 비밀번호 변경이나 포인트 사용
  - 어려운 케이스(25%): 피해자와 같은 도시의 국내 IP를 쓰고, 절반은 기기 지문까지 위조

## 구조

```
로그 → [1] 규칙 (rules.py)       IP별 실패 급증 · 한 IP로 여러 계정 시도 · 악성/데이터센터 IP
     → [2] 특징 (features.py)    사용자별 평소 대비: 새 기기·국가·지역, 접속 시각 차이,
                                  직전 로그인 대비 이동 속도(불가능한 이동), 계정 실패 횟수
     → [2] 모델 (model.py)       Isolation Forest(비지도), 점수 = 학습 기간 대비 백분위
     → [3] 판정 (risk.py)        통과 / 추가 인증(≥0.97) / 차단(≥0.995 + 규칙·불가능 이동 근거)
                                  로그인 직후 민감 행동은 문턱을 0.85로 낮춰 한 번 더 확인
     → 요약 (summarize.py)       운영자용 한 줄 근거. GEMINI_API_KEY가 있으면 LLM으로 다듬음
```

설계 원칙
- 모든 특징과 규칙은 **그 시점까지의 과거 로그만** 봅니다(미래 정보 누수 없음).
- 실패한 로그인은 사용자 '평소 패턴'에 넣지 않습니다. 공격 시도가 기준을 오염시키지 않게 하려는 것입니다.
- **모델 점수만으로는 차단하지 않습니다.** 차단하려면 규칙 근거나 불가능한 이동이 함께 있어야 합니다. 정상 사용자를 막는 사고를 줄이기 위한 장치입니다.

## 결과 (합성 데이터, 뒤 30일 섀도 모드)

| 방식 | 탐지율(공격자 로그인 성공 기준) | 오탐(정상 로그인 추가 인증) |
|---|---|---|
| 규칙만 | 53.5% | 0.0% |
| 모델만 | 93.0% | 2.2% |
| 규칙 + 모델 + 위험도 대응 | **93.0%** | 2.6% (차단 0.0%) |

- 스터핑 시도 2,889건 중 98.9% 차단, 스터핑으로 뚫린 계정 100% 탐지
- 표적 탈취 85% 탐지. 놓친 3건은 모두 **기기 지문을 위조한 국내 로그인**입니다. 로그인 시점 특징만으로는 한계가 있고, 로그인 이후 행동 특징이 필요하다는 근거입니다.
- 합성 데이터라서 실제 성능을 보장하지 않습니다. 실서비스에서는 0단계(현황 측정)부터 다시 재야 합니다.

전체 리포트와 운영자 요약 예시: [reports/shadow_report.md](reports/shadow_report.md)

## 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m atoguard.pipeline   # 생성 → 학습 → 판정 → reports/shadow_report.md
.venv/bin/python -m pytest -q
```

LLM 요약을 쓰려면 `GEMINI_API_KEY`를 설정합니다(무료 티어 가능, 모델은 `GEMINI_MODEL`로 변경). 키가 없으면 템플릿 요약을 씁니다.
